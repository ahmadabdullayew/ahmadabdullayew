# Visual profile system — v2.2

## Purpose and sources

Designed from the categories **Minimalistic**, **Descriptive**, and **Simple but Innovative Ones** in [abhisheknaiidu/awesome-github-profile-readme](https://github.com/abhisheknaiidu/awesome-github-profile-readme). The source is a curated set of profile links, not a copyable design specification. These graphics are newly authored for this profile; no screenshot, graphic, template code, or third-party badge was copied.

## Visual language

- **Identity**: original static headline graphic “BUILD. TEST. EXPLAIN.”, with a restrained signal/network motif. The name and specialization remain real Markdown text, not image-only identity.
- **Palette**: dark navy / ice blue with low-saturation teal and lavender accents. Light variants invert contrast intentionally rather than simply using white lettering.
- **Type**: system fonts with fallback to DejaVu Sans; SVG typography is presentational, while critical names and project evidence remain selectable Markdown.
- **Responsive**: four identity versions and four method versions (desktop/mobile × dark/light), selected with native `<picture>` sources, no CSS or JS.
- **Method panel**: 4 practices (define, baseline, evaluate, review), explicitly labeled as principles; not fabricated performance outcomes.
- **Projects**: real h3 headings and source/test links remain fully visible. No tiny chart, unreliable live badges, GIFs, or decorative performance metrics replace evidence.
- **Ownership**: all eight assets under `assets/` are reviewed source-controlled graphics, distinct from the five independently published GitHub contribution artifacts.

## Verification contract

All art remains static and motion-free; SVGs have `title`/`desc`, unique label IDs and no remote fetches. `profile-spec.json` registers exactly eight maintained graphics and four generated calendar SVGs. CI validates registration, alt text, references and XML. The visual check rasterizes responsive assets for legibility at 320/390px mobile and 768/1024/1440px desktop. These automated tests do not prove GitHub browser or assistive technology compliance; manual review remains required.

## Review checklist

- Inspect README in GitHub light and dark themes on mobile and desktop.
- Confirm the entire text on the identity and method graphics is legible on 320px screens.
- Confirm no untrusted third-party graphical content is embedded, and project links still lead to inspectable sources.
- Verify the contribution chart (the only API-generated image family) is not confused with the original identity banners.
